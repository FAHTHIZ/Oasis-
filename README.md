# OASIS

OASIS is a terminal coding agent. It is built on the open-source [pi](https://github.com/earendil-works/pi) engine (MIT) and adds the parts that decide whether an agent's work can be trusted: verification gates, a parsed-shell safety policy, an OS sandbox, file checkpoints and memory across sessions, with sub-agents and messaging gateways next.

The goal is to match or beat Claude Code, Codex, Hermes Agent and Google Antigravity on reliability, not just on feature count. See [docs/RESEARCH.md](docs/RESEARCH.md) for the comparison and the reasoning behind every component.

## Install

Requires Node.js 22.19 or newer.

```sh
git clone https://github.com/FAHTHIZ/Oasis-.git oasis
cd oasis
npm install
npm run build
npm link        # puts `oasis` on your PATH
oasis
```

Inside the app, run `/login` to sign in to a provider, or set an API key such as `ANTHROPIC_API_KEY` or `OPENAI_API_KEY`. Settings, sessions and credentials live in `~/.oasis/`; project settings live in `.oasis/` in your repository.

## What OASIS adds on top of pi

| Extension                  | What it does                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Turn gates                 | Before the agent finishes, its reply is checked against what actually happened. Edits with no passing check, "all tests pass" after a failing or piped run, "updated X" when the edit to X failed, tests skipped or weakened to make them pass, empty replies, and early stops on a change request (steps handed to you instead of the change, "I'll do X next" and then stopping, giving up after one tool error, canned refusals, "I've updated X" when nothing changed) each get one hidden reminder. If the problem remains, you see a short "Not verified" or "Not done" note instead of a silent false "done".                                                                                                                                                                                                                                                                                                                   |
| Shell safety policy        | Every `bash` call is parsed with [unbash](https://github.com/webpro-nl/unbash) and checked as an AST, so `sudo rm -rf /`, `curl … \| sh`, `mkfs`, `dd` to a disk or a fork bomb are blocked even when hidden behind `&&`, `$(…)`, `sudo` or `env`. Also blocked: `cd ~ && rm -rf *`, deleting private keys, writing system files, force-pushing, publishing packages and deleting a remote repo. High-risk commands that are sometimes intended (`git reset --hard`, `branch -D`, `clean -x`, `docker system prune`, `kubectl delete`, `terraform destroy`, `DROP TABLE`, appending to `~/.bashrc`, `base64 -d \| sh`) run only after you approve them, and are blocked when nobody can approve.                                                                                                                                                                                                                                       |
| Checkpoints                | Your files are snapshotted before every prompt into a separate shadow git repo, so `/undo` reverts everything the last prompt changed, including changes made by shell commands, and `/redo` puts it back. `/fork` and `/tree` offer to rewind files with the conversation. Works in folders that aren't git repos; your own `.git` is never touched.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| Memory                     | The agent keeps small notes files about you (`USER.md`), your environment (`MEMORY.md`) and each repository (a per-project `MEMORY.md` shared by all its worktrees), shown to it at the start of every session. Several changes go in one all-or-nothing batch, and a miss lists the closest entries; entries are scanned for prompt injection and secrets. `session_search` finds anything said in past sessions (SQLite full-text search, no extra install). `/memory` shows what it remembers.                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Sandbox                    | Shell commands run under OS isolation via [sandbox-runtime](https://github.com/anthropics/sandbox-runtime) (Seatbelt on macOS, bubblewrap on Linux): writes stay in the project, credentials like `~/.ssh` and `~/.aws` are unreadable, and network is limited to package registries and git hosts, with others asked about. `--sandbox read-only` or `--sandbox off` to change it.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Task list                  | A `todo` tool for multi-step work (the whole list is rewritten each call, one item in progress at a time, cancelled items need a reason), shown above the editor while the agent works and kept in the session tree so `/fork` and `/tree` bring back the matching list. An open-todos gate stops the agent from ending with pending items unless it is asking you a question. `/todos` shows the list.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| Project instructions       | Repositories set up for Claude Code, Codex or Cursor work as-is: `AGENTS.md` and `CLAUDE.md` in every parent folder (both, not one or the other), `CLAUDE.local.md`, `~/.claude/CLAUDE.md`, `.cursorrules`, `.github/copilot-instructions.md`, `.claude/rules/` and `.cursor/rules/`. `@path` imports are expanded and HTML comments removed. Rules with `paths:` or `globs:` and `CLAUDE.md` files in subfolders load only when the agent touches a matching file. `.claude/skills` and `.claude/commands` load as skills and prompts. `/instructions` lists what was loaded.                                                                                                                                                                                                                                                                                                                                                         |
| Reliability                | Doom-loop detection: the third identical tool call in a row gets a note to change course, the fifth is blocked, the eighth stops the run; cycles like read, grep, read, grep are flagged too. Model fallback: when a provider keeps failing after the automatic retries (overloaded, rate limited, server or auth errors), OASIS switches to the next model in `--fallback-model` or `fallbackModels` in settings and carries on, then returns to your model for the next prompt. A per-model circuit breaker keeps OASIS on the fallback after two failed runs in a row, and lets one probe prompt through after a cooldown (30 seconds, doubling up to 30 minutes); `/breakers` shows them.                                                                                                                                                                                                                                          |
| Language servers           | `lsp` asks the project's language server, as in Claude Code and OpenCode: definition, references, hover, implementation, type definition, document and workspace symbols, incoming and outgoing calls, diagnostics. Built in for TypeScript/JavaScript (typescript-language-server, `tsc --lsp`, tsgo), Python (pyright, basedpyright, pylsp), Go, Rust, C/C++, Java, Ruby, PHP, Lua, C#, Kotlin and Swift; more under `lspServers` in settings. After `write` or `edit`, errors the change introduced are appended to the result. `OASIS_LSP=0`, `OASIS_LSP_DIAGNOSTICS=0`.                                                                                                                                                                                                                                                                                                                                                           |
| Jupyter notebooks          | `read` of a `.ipynb` shows its cells and text outputs instead of raw JSON, and `notebook_edit` replaces, inserts or deletes one cell, as Claude Code's NotebookEdit (same name for hooks and agent files). Writes are atomic and keep the file's indentation; the sandbox and protected-path checks apply. `OASIS_NOTEBOOK=0`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Structural search          | `ast_grep` finds code by shape with ast-grep, as in the original OASIS and Claude Code setups: `foo($A, $$$REST)`, `def $F($$$P): $$$B`, regardless of layout, comments or strings. In-process through `@ast-grep/napi` for TypeScript, TSX, JavaScript, HTML, CSS, Python, Go and Rust, plus any other installed `@ast-grep/lang-*` grammar. With `rewrite` it previews a diff and returns ready-made `edit` calls, so nothing bypasses the edit guards. `OASIS_AST_GREP=0`.                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Syntax check               | After `write` or `edit`, syntax errors the change introduced are appended to the result, from in-process parsers only: tree-sitter for code and CSS, jsonc-parser for JSON (comments allowed in tsconfig, `.vscode` and `.jsonc`), yaml, smol-toml, and for HTML inline `<script>`/`<style>` plus local `src`/`href` files that do not exist. Works with no language server or test runner. `OASIS_SYNTAX_CHECK=0`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Repo map                   | `repo_map` gives a ranked outline of the codebase, as in Aider: top-level definitions from real tree-sitter grammars (TypeScript, JavaScript, Python, Go, Rust, Java, C#, C/C++, Ruby, PHP, Bash; line patterns for Kotlin, Swift, Elixir, Lua and more), files ranked by personalized PageRank over which files use which symbols, comments and strings ignored. `focus` centres it on files or symbols. Scans are cached per file. Available in plan mode and to read-only subagents.                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| Scratch space              | Each session gets a git-ignored `.oasis/scratch/<session>/` for throwaway repro scripts; not counted as project changes, pruned after a week (`OASIS_SCRATCH=0` off)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| Follow-ups                 | "Next steps:", "Not sure about:", "Remaining:" items from final replies are saved per project and shown at the next session start; `/followups` (`OASIS_FOLLOWUPS=0` off)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| Model routing              | Short read-only questions go to a cheaper model (`OASIS_EASY_MODEL=provider/id` or `modelRouting.easyModel`), everything else stays on the main model; `/route` explains a decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Goals                      | `/goal CONDITION` (or `-p --goal`) keeps working until a strict reviewer model says the condition is met and verified; pause, resume, edit, clear; `OASIS_GOAL_TURNS` caps checks                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Editor integration         | `oasis acp` speaks the Agent Client Protocol (via the MIT pi-acp adapter), so Zed, JetBrains and other ACP clients run OASIS with every extension: `"agent_servers": {"OASIS": {"command": "oasis", "args": ["acp"]}}`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Background commands        | `bash` takes `run_in_background` for servers and watchers (same sandbox and guards); `bash_output` reads new output (filter, wait), `kill_shell` stops it, `/bashes` lists them                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Ask the user               | `ask_user_question`: multiple-choice question (or a typed answer) for real decisions; at most 2 per prompt (`OASIS_MAX_QUESTIONS_PER_TURN`); without a UI the model decides and states its assumption                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| Background agents          | `task` with `run_in_background` returns at once; the report arrives as a message when the subagents finish; `task_output` checks early, `/tasks stop ID` cancels                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Output styles              | Claude Code-compatible `/output-style [name]` (or `--output-style`, `OASIS_OUTPUT_STYLE`, `"outputStyle"` in settings.json): built-in `default`, `concise`, `explanatory`, `learning` (leaves small `TODO(human)` pieces for you), `architect` and `reviewer`, plus custom Markdown styles from `~/.claude/output-styles`, `~/.oasis/agent/output-styles` and, in trusted projects, `.claude/output-styles` and `.oasis/output-styles`. The choice is saved per session.                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| Session messaging          | Several Oasis sessions in one workspace can coordinate: `/peers` lists live sessions, `/notify <id-or-name> <message>` leaves one a note, and the agent can do the same with `session_message`. Notes reach a running turn as steering or wait for the next turn, are marked as peer notes rather than user instructions, and never start a turn by themselves. Same workspace and live processes only, 4000 characters, 12 per minute, no forwarding. `OASIS_SESSION_MESSAGES=0` turns it off.                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Side questions and advisor | Claude Code's `/btw QUESTION` asks the current model about the session and shows the answer without adding it to the conversation; `/recap` gives a one-line summary. With `/advisor provider/model` (or `--advisor`, `OASIS_ADVISOR_MODEL`), the agent gets an `advisor` tool to consult a second, usually stronger model that sees the transcript and returns guidance only.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Codex apply_patch          | GPT-5 and Codex models edit with OpenAI's V4A `*** Begin Patch` format, as an `apply_patch` call or `apply_patch <<'EOF'` in the shell. Oasis plans the whole patch against the files on disk (with whitespace-tolerant context matching and CRLF/BOM preservation) and turns it into ordinary `write` calls plus one `bash rm` for deleted or moved files, so every permission, protected path, hook, sandbox and checkpoint rule still applies. If any hunk does not match, nothing is written and the model is told which lines were not found.                                                                                                                                                                                                                                                                                                                                                                                     |
| Status line                | Claude Code's `"statusLine": {"type": "command", "command": "..."}` from `~/.claude/settings.json`, `~/.oasis/agent/settings.json` or, in trusted projects, `.claude/` and `.oasis/` settings. The command gets Claude Code's session JSON on stdin (model, workspace, cost, context window, output style) and its first line is shown in the footer after each turn, on model changes and every `refreshInterval` seconds.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| AI comments                | Aider-style watch mode: with `oasis --watch-files` or `/watch`, a comment ending in `AI!` in any file, from any editor, asks for a change, one ending in `AI?` asks a question, and plain `AI` adds context (`//`, `#`, `--`, `/* */`, `<!-- -->` and trailing comments). Each new set becomes a prompt with the surrounding code (queued as a follow-up while the agent is busy); the agent removes the comments it handled. Comments that existed before watching started never fire; secret files and agent-ignored paths are skipped.                                                                                                                                                                                                                                                                                                                                                                                              |
| Safe mode                  | `oasis --safe-mode` (or `OASIS_SAFE_MODE=1` / `CLAUDE_CODE_SAFE_MODE=1`) starts with every customization off, as in Claude Code: `CLAUDE.md`/`AGENTS.md`, skills, prompt templates, discovered extensions and packages, hooks, MCP servers and custom agents. Logins, models, built-in tools, memory, permission rules and the safety policy keep working, so if a problem goes away the cause is one of your customizations.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Doctor                     | `oasis doctor` and `/doctor` check the install and the project, as Claude Code's `/doctor` does: Node version, git and ripgrep, native modules (ast-grep, SQLite), model credentials, every settings file (invalid JSON is called out), permission rules that cannot be read, hook and MCP commands that are not installed, oversized `CLAUDE.md`/`AGENTS.md`, language servers, project trust, stale `.git/index.lock`, and cron jobs. `fix` (`oasis doctor --fix`, `/doctor fix`) repairs OASIS's own state: stale locks, stuck cron claims, jobs whose directory is gone and leftover temp files; your settings files are never rewritten.                                                                                                                                                                                                                                                                                          |
| Scheduled jobs             | Hermes-style cron: the `cronjob` tool (create, list, update, pause, resume, run, remove, runs) schedules agent prompts or plain shell scripts that need no model, on a cron expression with an optional time zone, `every 2h`, `in 30m`, an ISO time or `weekdays at 9am` (next-run math by [croner](https://github.com/hexagon/croner)). Each run is a fresh `oasis -p` session in the job's directory with the same safety rules; slots missed by more than half a period are skipped rather than fired late; `[SILENT]` output is kept but not announced. Jobs fire while a session is open, from `oasis cron daemon`, or from a crontab line `* * * * * oasis cron tick`; results that finished while you were away are shown at the next start. Scheduled runs cannot create jobs. `/cron`, `oasis cron list\|run\|runs\|pause\|resume\|remove`; `OASIS_CRON=0` turns it off.                                                     |
| Topic notes                | Claude Code-style auto memory beside the bounded Hermes files: the `notes` tool keeps one Markdown file per topic (preferences, project, decisions, lessons, people, reference) for the project or for you everywhere, merges near-duplicates and redacts secrets. A one-line index goes into the system prompt, and each prompt recalls the full text of the few notes that match it (BM25 with Porter2 stemming, via MiniSearch). Project facts carry a freshness verdict and can be marked current or outdated with evidence; a full store archives its least valuable note. `/notes` lists them.                                                                                                                                                                                                                                                                                                                                   |
| Standing corrections       | Tell OASIS "stop saying 'load-bearing'" once and it sticks: the phrase is saved to `~/.oasis/agent/corrections.json`, restated in the system prompt every turn (so compaction cannot drop it) and in later sessions, and a final reply that still uses it is sent back once for a rewrite. Code spans are ignored. `/corrections` lists them, `/corrections remove <phrase>` and `/corrections clear` undo them.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Tolerant edits             | When an edit's `oldText` is not in the file even after pi's own whitespace and quote normalization, OASIS looks for a unique match that ignores indentation, spacing next to punctuation, or line numbers copied from `read` output, and re-indents the replacement into the file's style (four spaces to tabs and so on). Ambiguous matches are refused. A failed edit shows the closest region of the file with line numbers so the model can fix it in one step. `OASIS_EDIT_MATCH=0` turns it off.                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Context savings            | Re-reading an unchanged file range while the earlier result is still in context returns a short pointer instead of the same text. Once the context is half full, older `read` and `bash` results that a newer one fully covers are stubbed in what the model sees (the session keeps everything). Passing-test chatter (TAP, `go test -v`), npm update banners and progress redraws are dropped from command output. `OASIS_READ_DEDUP=0`, `OASIS_SUPERSEDE_RESULTS=0` and `OASIS_CONDENSE_OUTPUT=0` turn each off.                                                                                                                                                                                                                                                                                                                                                                                                                    |
| MCP                        | pi's MCP client (stdio and streamable HTTP, OAuth sign-in, resources, `/mcp`, `oasis mcp add`) reads `~/.oasis/agent/mcp.json` and `.oasis/mcp.json`. OASIS also loads the servers you set up for Claude Code: `~/.claude.json` (user and local scopes) and the project's `.mcp.json` in trusted projects, with `${VAR:-default}` expansion and `disabledMcpjsonServers`. Every MCP tool is checked before it runs: descriptions that hide instructions, point at credential files or carry invisible characters, and tools whose definition changed since first use ("rug pulls"), need your approval.                                                                                                                                                                                                                                                                                                                                |
| Protected config           | Writes to files that decide what runs later without asking (`.oasis`/`.claude` settings, hooks and plugins, `.mcp.json`, `.git/hooks` and command-running git config keys, VS Code tasks, `.envrc`, Husky and pre-commit hooks, `.npmrc`...) always ask first, through `write`, `edit` or `bash`, even when symlinked; without a UI they are blocked. `OASIS_ALLOW_CONFIG_EDITS=1` turns this off.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| Agent ignore files         | Paths matched by `.oasisignore`, `.cursorignore` (Cursor), `.devinignore`, `.codeiumignore` (Windsurf, also the global one), `.geminiignore`, `.aiexclude` or `.aiderignore` are refused by `read`, `write`, `edit`, `lsp`, `ast_grep` and `repo_map` and left out of `grep`, `find`, `ls`, repo map and structural search results. Gitignore syntax via node-ignore; each folder up to the git root can add its own. Like Cursor, this cannot stop a shell command. `OASIS_AGENT_IGNORE=0`.                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| Progress guards            | When the same command keeps failing the same way across three rounds of edits, the result asks the agent to re-read the error and test a hypothesis before editing again; at five it is told to stop patching and report. A state-changing command (not read-only, not a check) repeated with no edits in between gets a warning that its effect was repeated. `OASIS_PROGRESS_GUARD=0` turns it off.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| No-op edit check           | When `sed -i`, `perl -pi` or an inline Python/Node/Ruby replace script exits 0 but every file it names is byte-for-byte unchanged, the result says the pattern most likely did not match, so the agent does not claim a change that never happened. `OASIS_NOOP_EDIT_CHECK=0` turns it off.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Package vetting            | Before bash installs packages (npm, pnpm, yarn, bun, pip, uv, poetry, pdm, rye, cargo), each name is checked on its registry and OSV.dev. Invented names are blocked; lookalikes of the top 3000 packages, packages first published in the last 30 days, under 50 weekly downloads, or reported malicious need your confirmation; known vulnerabilities are noted. Network problems never block. `OASIS_PACKAGE_VETTING=0` turns it off.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| Git safety snapshots       | Before bash runs something that throws away uncommitted work (`git checkout .`, `git restore`, `git reset --hard`, `git clean -f`, `git stash drop`, `rm`, `find -delete`), the whole working tree, untracked files included, is saved to `refs/oasis/safety/` through a throwaway index, and the result says how to restore it. Your index, stash and branch are untouched; the newest 30 snapshots are kept. If the snapshot fails, the command is not run. `OASIS_GIT_SAFETY=0` turns it off.                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Commit secret gate         | A `git commit` run through bash is blocked before it runs when the commit would add what looks like a real credential (staged changes, tracked changes for `commit -a`, everything not ignored when the same command runs `git add`). The scan uses a throwaway copy of the index and never touches yours. `OASIS_COMMIT_SECRET_SCAN=0` turns it off.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| Secret shield              | API keys, tokens, passwords, private keys and credential URLs in tool output are replaced with `«secret:ID»` placeholders before the model or the saved session sees them (Gitleaks' 220 maintained rules plus provider-prefix, `KEY=value`, URL and `Authorization` patterns). The agent uses the placeholder in edits and commands and OASIS swaps the real value in just before the tool runs, so it can still fix your `.env` without the key ever reaching the provider. Web and subagent calls keep placeholders. `OASIS_SECRET_SHIELD=0` turns it off.                                                                                                                                                                                                                                                                                                                                                                          |
| Web                        | `web_fetch` reads any public page as Markdown (Defuddle main-content extraction; docs sites that serve Markdown are asked for it), paged for long pages. `web_search` fuses Tavily, Brave, Exa, Firecrawl and SearXNG results by rank when their keys are set, and falls back to keyless DuckDuckGo and Bing. Local, private-network and cloud-metadata addresses are blocked, DNS answers are pinned and every redirect hop is checked again. Fetched pages and MCP results pass an untrusted-content guard: hidden Unicode is removed, injected instructions are flagged, and network commands then need your approval for the rest of the task.                                                                                                                                                                                                                                                                                     |
| Skills that learn          | The agent saves what it worked out as skills with `skill_manage` (create, patch, delete, supporting files under `references/`, `scripts/`...), Hermes-style. New skills go to `~/.oasis/agent/skills` or the project's `.oasis/skills`; existing ones, including `.claude/skills` and `.agents/skills`, are patched in place. Content is checked against the Agent Skills spec and scanned for prompt injection, secrets and dangerous commands. After a long run with nothing saved, a background reviewer agent reads a condensed transcript and saves skills or memories while you carry on (`--learning nudge` adds a hidden reminder to the next prompt instead; `--learning off` disables it). `/skills` lists them.                                                                                                                                                                                                             |
| Plan mode                  | `/plan` (or `/plan <task>`, or `--plan`) makes the agent research read-only and end with `exit_plan_mode`, which asks you to approve the plan before anything changes. `bash` still runs read-only commands (`ls`, `cat`, `rg`, `git status/log/diff`...), checked by an AST classifier that rejects writes, redirects, `sed -i`, `find -delete`, `eval` and anything it can't prove safe. The explore and plan subagents use the same rules.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Permission rules           | Claude Code `permissions` rules work unchanged from the same settings files: `"allow"`, `"ask"` and `"deny"` lists with `Bash(npm run test:*)`, `Bash(git push *)`, `Read(./.env)`, `Edit(/migrations/**)`, `WebFetch(domain:docs.rs)`, `Tool(param:value)`, `mcp__server` and `*`. Deny beats ask beats allow; a compound shell line is allowed only when every command in it is. Allow rules skip the safety question (catastrophic commands stay blocked); project allow rules count only in trusted projects. `/permissions` lists them; `OASIS_PERMISSIONS=0` turns them off.                                                                                                                                                                                                                                                                                                                                                     |
| Hooks                      | Claude Code hooks run unchanged: the `hooks` block of `.claude/settings.json`, `.claude/settings.local.json`, `~/.claude/settings.json`, `.oasis/settings.json` or `~/.oasis/agent/settings.json` (PreToolUse, PostToolUse, UserPromptSubmit, Stop, SubagentStop, SessionStart, SessionEnd, PreCompact). Same stdin JSON, tool names (`Bash`, `Edit`, `Write`...), matchers, exit code 2 to block, and JSON output (`permissionDecision`, `updatedInput`, `additionalContext`, `decision: "block"`). Command and HTTP hooks; project hooks only in trusted projects. `/hooks` lists them.                                                                                                                                                                                                                                                                                                                                              |
| Subagents                  | A `task` tool hands a self-contained job to a fresh agent with its own context and gets back only its final report, so long searches don't fill the main conversation. Built-in `explore` (read-only search), `plan` (read-only planning) and `general` agents; up to 8 tasks in parallel; an optional JSON Schema the reply must match. Agent files from Claude Code (`.claude/agents/*.md`, `~/.claude/agents`) work unchanged, as do `.oasis/agents`. Children keep the safety policy, sandbox and gates. `isolation: "worktree"` (on the call or in the agent's frontmatter, as in Claude Code) gives each agent its own git worktree and branch, so parallel agents can edit without touching your checkout; changes come back as a commit on that branch, unchanged worktrees are removed, and Cursor/Windsurf/OpenHands worktree setup files run in trusted projects. `/agents` lists them, `/worktrees` lists agent worktrees. |
| Tool-call repair           | Models trained on other harnesses call `Bash`, `Read`, `MultiEdit`, `TodoWrite` (Claude Code), `shell` and `update_plan` (Codex), `run_shell_command` (Gemini CLI) or `terminal` (Hermes). OASIS maps those names and their arguments (`file_path`, `old_string`, argv arrays, millisecond timeouts) onto its own tools before anything runs, so safety and gates still apply. A truly invented tool gets the list of real tools and the closest match instead of a bare "not found".                                                                                                                                                                                                                                                                                                                                                                                                                                                  |

Everything pi provides comes with it: the TUI, sessions as a branching tree, compaction, skills, prompt templates, MCP, codemode, RPC/JSON modes, 20+ model providers and extension packages.

npm run check      # biome lint + tsc + vitest
