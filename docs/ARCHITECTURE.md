# Architecture

OASIS is a thin product layer on the pi engine. pi owns the agent loop, sessions, TUI, providers and built-in tools. OASIS owns behaviour, packaged as pi extensions.

```
bin/oasis.mjs          sets PI_PACKAGE_DIR, loads dist/cli.mjs
  src/cli.ts           main(argv, { extensionFactories: oasisExtensions() })
    pi-coding-agent    TUI, print/JSON/RPC modes, sessions, compaction, tools
      pi-agent-core    agent loop, tool execution, event stream
      pi-ai            providers, streaming, auth
    src/extensions/    OASIS behaviour
```

## Identity

pi reads its app name and config directory from the `piConfig` field of the package it believes it belongs to. `scripts/copy-pi-assets.mjs` writes `dist/pi-runtime/` with OASIS's `package.json` (name, version, `piConfig: { name: "oasis", configDir: ".oasis" }`) and copies pi's static assets (themes, export-html templates, docs, examples) next to it. `bin/oasis.mjs` points `PI_PACKAGE_DIR` there.

The runtime directory is separate from the repo root on purpose: pi treats a package directory containing `src/` as a source checkout and looks for assets under `src/`, which would break in development.

Result: the binary is `oasis`, user data lives in `~/.oasis/agent/`, project settings in `.oasis/`, and the agent-dir override variable is `OASIS_CODING_AGENT_DIR`.

### Gates

| Gate                | Fires when                                                                                                                                                                                                                                                                                                                                                 |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `test-tamper`       | A test or test-config file now has a skip, `.only`, fewer tests or assertions, exact assertions loosened to truthiness, swallowed assertion errors, or a test command that always succeeds, compared with its content just before the agent's first edit this prompt (diffed with `jsdiff`). Skipped when the user asked to skip, remove or disable tests. |
| `failed-edit-claim` | The reply says a file changed, but the edit to it failed and was not redone.                                                                                                                                                                                                                                                                               |
| `false-pass-claim`  | The reply says tests or builds pass, but no check ran, the last check failed, its exit status was hidden, it did not finish, or files changed after it.                                                                                                                                                                                                    |
| `unverified-edits`  | Files were edited and no passing check ran afterwards, and the reply does not plainly say so.                                                                                                                                                                                                                                                              |
| `empty-reply`       | The final reply has no text.                                                                                                                                                                                                                                                                                                                               |

### Shell analysis

`src/shell/` parses each command once with unbash and answers two questions:

- `policy.ts`: is this command catastrophic? Wrappers (`sudo`, `env`, `timeout`, ...) are unwrapped and every command inside `&&`, `;`, pipelines, subshells and `$(...)` is checked.
- `checks.ts`: is this a verification command, and does its exit status reach us? `statusCommands()` in `ast.ts` works out which commands can determine the script's exit status, so `npm test | tail`, `npm test || true`, `npm test; echo done` and `! npm test` count as masked, while `npm test && echo ok` and `set -o pipefail; npm test | tail` do not. Paths like `cat test/foo.js` are not mistaken for test runs.

Rules for new extensions:

1. One behaviour per file, no shared mutable state between extensions.
2. Anything returned from `agent_before_settle` must keep `event.entries`.
3. Bound every automatic continuation (count per user prompt) so the agent can never loop.
4. Every behaviour gets an end-to-end test in `test/` using the faux-provider harness.

## Sandbox

| Mode                        | Shell writes                       | File tool writes   | Network                                                                                             |
| --------------------------- | ---------------------------------- | ------------------ | --------------------------------------------------------------------------------------------------- |
| `workspace-write` (default) | Project, temp dirs, package caches | Project, temp dirs | Package registries and git hosts; other hosts are asked about in the TUI, blocked in print/JSON/RPC |
| `read-only`                 | Temp dirs, package caches          | Temp dirs          | Same                                                                                                |
| `off`                       | Anything                           | Anything           | Anything                                                                                            |

In every sandboxed mode, commands cannot read `~/.ssh`, `~/.aws`, `~/.gnupg`, `~/.kube`, cloud CLI configs, `~/.npmrc`, `~/.netrc`, git credentials or OASIS's own `auth.json`, and cannot write `.git/hooks` or `.git/config` (both would let code run outside the sandbox later).

Mode comes from `--sandbox`, then `OASIS_SANDBOX`, then `~/.oasis/agent/sandbox.json`, then the default. Only the user's own `sandbox.json` can widen the policy (`allowWrite`, `allowedDomains`, `denyRead`, `deniedDomains`, `askForUnknownHosts`); nothing inside a project can, so a cloned repository can't grant itself access. If the platform or its dependencies (bubblewrap and socat on Linux) are missing, OASIS warns and runs commands without OS isolation; the file-tool path checks still apply.

## Checkpoints

`src/checkpoints/shadow-git.ts` keeps one bare-style git directory per project at `~/.oasis/agent/checkpoints/<sha256(path)[:16]>`, with `GIT_DIR` pointing there and `GIT_WORK_TREE` at the project. Global and system git config, hooks and inherited `GIT_*` variables are ignored, so user settings can't redirect it. A snapshot is `add --all` + `write-tree` + `commit-tree` + `update-ref`; it honours the project's `.gitignore` files and skips `node_modules`, virtualenvs, build caches and OASIS's own data. Restoring first snapshots the current files (that snapshot is what `/redo` returns to), deletes files that did not exist at the checkpoint, then `read-tree` + `checkout-index --force --all`. The user's own `.git` is never read or written, and nested repositories are recorded as gitlinks rather than copied. Checkpoints are off when the working directory is the home directory or filesystem root.

Each checkpoint is a `custom` session entry (`oasis.checkpoint`: commit, tree, prompt, time), so it follows the session tree: `/undo` only considers checkpoints on the current branch, and they survive restarts.

## Memory

`src/memory/store.ts`: entries separated by a `§` line, 2,200 characters for MEMORY.md and 1,375 for USER.md (Hermes' budget). `add` rejects exact duplicates; `patch` replaces one span inside the single entry that contains it (or rewrites an entry passed whole); `remove` deletes by unique substring. A write that would exceed the limit fails with the current contents so the agent consolidates; nothing is dropped silently. Every entry is scanned for invisible Unicode, prompt-injection phrasing, credential exfiltration commands, SSH keys and common token formats before it is written. Files are written atomically (temp file + rename) under `~/.oasis/agent/memory/`, which the sandboxed modes keep out of reach of shell and file tools, so there the scanned tool is the only way in.

Project memory uses the same format in `~/.oasis/agent/projects/<key>/memory/MEMORY.md` with a 4,000-character limit. The key is the main work tree path with separators replaced by `-`; a linked worktree's `.git` file (`gitdir: <main>/.git/worktrees/<name>`) maps back to the main tree. `apply()` runs a batch of operations against in-memory copies, checks every touched file against its limit, then writes them; any failing operation aborts the batch with its index. Misses list up to three entries ranked by shared words.

`src/memory/session-index.ts`: `~/.oasis/agent/memory/sessions.db` (WAL) with `files` (path, session id, cwd, title, byte offset), `messages` and an external-content FTS5 table kept in sync by triggers. Each search first indexes new bytes of every session file (only complete lines), drops files that were deleted and restarts files that shrank. Indexed text: user and assistant text, tool calls as `[tool] command-or-path`, tool output and `!` shell output cut to 1,200 characters. Free-text queries become quoted terms, all required, then any; queries using FTS5 syntax are tried as written first. At most three hits per session, ranked by bm25 then recency; search defaults to sessions from the same directory and leaves out the current one.

### Project instructions

`src/memory/instructions.ts` walks from the filesystem root to cwd and loads, per directory, `AGENTS.override.md`, `AGENTS.md`, `CLAUDE.md`, `.claude/CLAUDE.md` and `CLAUDE.local.md` (the home directory itself is skipped; `~/.claude/CLAUDE.md` is the user file). At the project root (nearest `.git`, else cwd) it adds `.cursorrules`, `.windsurfrules`, `.github/copilot-instructions.md`, every `*.md` under `.claude/rules` and `.oasis/rules`, and every `*.mdc` under `.cursor/rules`. Rules with `paths` (Claude Code) or `globs` (Cursor, comma string or list) are scoped and matched with minimatch against the path relative to the root; a glob without `/` matches the basename. Files over 4 MiB are skipped, as in Claude Code. Imports: `@path` tokens in prose (not fenced or inline code) that resolve to an existing file inside the project, cwd or home directory are appended after the importing file as `<imported>` blocks, each file once, up to four hops, never re-importing a file already in context. Files are de-duplicated by real path and by whitespace-normalised content.

### Topic notes

`src/memory/notes.ts` keeps one Markdown file per topic with front matter (name, one-line description, category, created/updated, recall count, verification status, verifiedAt and evidence) under `<agent dir>/notes/<category>/` for the user and `<agent dir>/projects/<key>/notes/<category>/` per repository (the same key as project memory), plus a generated `MEMORY.md` index in each. Writes are atomic and redacted with `redactSecrets`. `save` merges into a note with the same slug or a Jaccard similarity of at least 0.75 on name and abstract (appending, or replacing when the bodies are 85% alike or `replace` is set); at 500 notes the least valuable one (outdated first, then old and never recalled) moves to `.archive/`. Ranking is MiniSearch BM25+ over name, description and body (the first two boosted twice, prefix matches for terms of four letters or more) with stop words dropped and Porter2 stemming, times a small boost for recent and often-recalled notes. Notes in project, decisions, lessons and reference categories are time sensitive: unverified, current (verified after the last change, within 90 days), stale, uncertain or outdated. The extension freezes the index (8,000 characters, most valuable first, outdated left out) into the `notes` prompt section at session start; each user prompt recalls up to three notes scoring at least 45% of the best hit, 4,000 characters in all, as a hidden message, each note once per context window.

## Repo map

`src/code/ast.ts` loads one tree-sitter runtime per process from `@vscode/tree-sitter-wasm` (the WebAssembly build VS Code ships) and a definitions query per grammar: functions, classes, methods, interfaces, types, enums, Rust items, Go types and the like. Definitions inside a function body are dropped as local helpers; those inside a class, impl or module body are marked as members. A second query over every comment and string node type blanks those ranges (keeping offsets and line breaks), so identifier uses are counted in code only. Languages without a bundled grammar use per-language line patterns.

`src/code/repo-map.ts` lists source files with `git ls-files --cached --others --exclude-standard` (a directory walk outside git), skipping dependency and build directories, minified files and credential files. Each scan (definitions, identifier counts, import specifiers) is cached in memory and on disk by mtime and size, invalidated with the grammar package version. Ranking follows Aider: an edge from A to B for each name A uses that B defines and can export (ES module exports, Go capitalised names, not test helpers), weighted by sqrt of the use count, up for compound names, down for common or widely defined ones, doubled when A imports B and nearly zero when A imports other modules but not B; resolved relative JS/TS and Python imports add their own edges, and reverse edges at a quarter weight lift callers. Personalized PageRank (40 iterations, damping 0.85) teleports to focus files and files mentioning focus symbols, or everywhere with tests at 5%. File rank is scaled by how many distinct files use it, so small isolated clusters do not float up. Each file shows its best definitions (8, 14 or 40 by budget) and falls back to a header line when the budget runs out.

## Structural search

`src/code/ast-grep.ts` loads `@ast-grep/napi` once and registers every installed `@ast-grep/lang-*` grammar with `registerDynamicLanguage`. Files come from the repo map's `git ls-files` listing (dependency directories and secret files skipped), filtered by path, globs and language. Each file is parsed in-process and searched with the pattern rule (optionally with a strictness). A rewrite fills the template from each match's captures (`$$$A` keeps the source between its first and last named node), drops replacements nested in an earlier one, and turns the result into `edit` edits, one per changed hunk, widened by whole lines until each `oldText` is unique. Nothing is written by the tool itself.

## LSP

`src/code/lsp.ts` speaks JSON-RPC over stdio (`vscode-jsonrpc`) to one server per language, started on first use with the project root as workspace and stopped, process group included, at session shutdown. Binaries come from `PATH`, or from `node_modules/.bin` and `.venv/bin` in trusted projects; TypeScript prefers typescript-language-server with the project's tsserver, then `tsc --lsp` (TypeScript 7) and tsgo. Documents are opened on demand and resent when their mtime or size changes. Requests wait for the server's work-done progress to end, since typescript-language-server answers from a syntax-only server while the project loads. Diagnostics are pulled when the server supports it, else taken from `publishDiagnostics`. For `write` and `edit`, the `tool_call` handler records the file's diagnostics before the change and `tool_result` appends errors that were not there before (compared as a multiset of severity, code and message, so shifted lines do not count). `.env` files and keys are refused.

## Reliability

`LoopDetector` keeps the last 64 call signatures (tool name plus arguments serialised with sorted keys) and resets on each user prompt. The streak of identical trailing signatures decides: 3 adds a note to the tool result, 5 or more blocks, 8 blocks with `terminate` and tells the user. Any different call breaks the streak, so `npm test` after each edit never counts. Cycles of length 2 or 3 repeated three times get one note per distinct cycle.

Fallback runs on `agent_before_settle` with outcome `error`, which pi reaches only after its own retries. If the last assistant message is a non-overflow error, the extension picks the first model in the chain (flag, then project settings, then user settings; `provider/id`, exact id or id substring) that hasn't been tried in this run and has configured credentials, switches with `pi.setModel`, and continues with a visible notice and a hidden "continue" message. `agent_settled` clears the tried set and switches back to the model the run started with.

## Standing corrections

Users report telling an agent to drop a phrase, only for compaction or a new session to erase the instruction. `src/memory/corrections.ts` (ported from the original OASIS) extracts phrases from user prompts ("stop saying 'X'", "don't use the word X", unquoted "stop saying X" up to four words; vague targets like "that" are skipped) and keeps the newest 30 in `<agentDir>/corrections.json`. Each run lists them in a `standing-corrections` system prompt section, which is rebuilt every turn. In `agent_before_settle`, a final reply whose prose (outside code spans) still uses a phrase gets one hidden rewrite request, like the turn gates.

## Tolerant edits

pi's edit tool already retries after stripping trailing whitespace and normalizing typographic quotes, dashes and spaces. `edit-match.ts` runs in `tool_call` before pi executes the edit: for each `edits[]` entry that pi would not match, `relaxedMatch` (ported from the original OASIS) tries, in order, ignoring indentation, ignoring spaces next to punctuation, and stripping consecutive line-number prefixes copied from `read` output. Only a unique block match is used; the arguments are rewritten to the file's real text and to a replacement re-indented into the file's indentation (mapping leading whitespace seen in the block, converting between indent units), with lines the model left unchanged copied verbatim and the file's typography kept. pi then runs an exact edit, so its own uniqueness and overlap checks still apply. When an edit fails with "Could not find", `closestMatchHint` adds the most similar region (bigram similarity, at least 50%) with line numbers.

## Context savings

Three lossless ways to keep the context small, ported from the original OASIS:

- **Read dedup.** `tool_result` on `read` hashes the text per absolute path + offset + limit. If the same range comes back identical while the earlier result is still in the last context sent to the model (not stubbed), the result becomes a pointer to it. Only once per range: a second repeat means the model lost track, so it gets the content.
- **Superseded results.** The `context` handler walks messages newest to oldest and replaces an older `read` whose line range (from `offset`/`limit` and pi's truncation notes) lies inside a newer real read of the same file, and an older run of an identical `bash` command (keeping its last 300 chars), with a stub. Blocked calls never cover anything. Rewriting old messages breaks the provider's prompt cache, which the original measured at +12% cost on short tasks, so this starts only once the context is 50% full and then stays on until compaction.
- **Output condensing.** `src/context/condense.ts` drops passing TAP subtest headers and timing-only YAML blocks, `go test -v` RUN lines of passing tests, npm update banners, and all but the last frame of carriage-return redraws. Failures keep every line.

## MCP

pi's built-in MCP extension owns connections, OAuth, resources, exposure (`codemode` by default, `deferred`, `direct`) and `/mcp`. `src/mcp/claude.ts` reads Claude Code's configuration: `mcpServers` in `~/.claude.json` (user), `.mcp.json` in the project root (project; only when `ctx.isProjectTrusted()`, minus `disabledMcpjsonServers` from Claude settings) and `projects[<root>].mcpServers` (local), in increasing precedence. Entries are converted to pi's shape with Claude's `${VAR}`/`${VAR:-default}` expansion; `sse` entries and values starting with `!` (which pi would run as commands) are reported and skipped. A server of the same name in OASIS's `mcp.json` wins.

`src/mcp/trust.ts` inspects a tool's description and schema text with the untrusted-content detector plus poisoning signals (hidden `<IMPORTANT>` blocks, credential-file references, instructions about other tools, redirected recipients, invisible characters) and fingerprints name, description, schema and annotations. On each `mcp__server__tool` call, including nested codemode calls, the extension compares the fingerprint with `~/.oasis/agent/mcp-pins.json` (first use pins it). Poisoned or changed tools need confirmation, which re-pins; without a UI they are blocked.

## Agent ignore files

`src/security/agent-ignore.ts` reads `.oasisignore`, `.cursorignore`, `.devinignore`, `.codeiumignore`, `.geminiignore`, `.aiexclude` and `.aiderignore` in the target's folder and each parent up to the git root (or the folder below home), plus `~/.codeium/.codeiumignore`, each cached for 1.5s and matched on its own with node-ignore. `agent-ignore.ts` blocks `tool_call`s whose `path` is ignored and, in `tool_result`, drops `grep`, `find` and `ls` lines that point at ignored paths with a note saying how many were left out. `listSourceFiles` (repo map, structural search) and the LSP result renderer check the same rules.

## Secret shield

`src/security/rules.ts` runs Gitleaks' rule set (`src/security/data/secret-rules.json`, MIT, translated from Go RE2 by the original OASIS): keyword prefilter, secret group or first capture, entropy threshold, rule and global allowlists. `src/security/secrets.ts` adds prefix-anchored token patterns, `KEY=value` assignments whose key names a secret, URL passwords and `Authorization` headers, and keeps a process-wide `SecretVault` (sha256 prefix to value, memory only; in-process subagents share it).

The extension is loaded last in both the main and subagent sets. `tool_result` masks text parts and string fields of plain-object details. `tool_call` restores placeholders in `event.input` in place; pi validates a `structuredClone` of the model's arguments, so the transcript keeps the placeholder. Network and agent-message tools (`NO_UNMASK_TOOLS`) are skipped so an injected page can't exfiltrate a value through a URL. A system prompt section explains placeholders to the model.

## Web

- `src/web/network.ts`: the SSRF policy. `isNonPublicIp` checks every IPv4/IPv6 spelling (parsed by ipaddr.js; IPv4-mapped and NAT64 addresses inherit the IPv4 table, anything outside 2000::/3 is non-public). `vetPublicUrl` rejects non-http(s) URLs, credentials in URLs, local names (`localhost`, `.local`, `.internal`, `.home.arpa`, GCP metadata) and hosts with any private DNS answer, and returns the vetted answers. `pinnedRequest` connects only to those answers, bounds the body and times out.
- `src/web/fetch.ts`: follows up to 5 redirects, vetting each hop; rewrites GitHub blob URLs to raw; asks for `text/markdown` first; converts HTML with `src/web/html.ts` (Defuddle over linkedom with network access disabled, unsafe URLs and hidden elements removed, nesting flattened past 64 levels, a whole-body retry when extraction keeps almost nothing); pages the result at paragraph boundaries.
- `src/web/search.ts`: runs every configured provider in parallel, filters domains, canonicalises URLs (tracking parameters removed) and merges rankings with reciprocal rank fusion (k = 60). With no provider or no results it falls back to DuckDuckGo's HTML endpoint, then Bing. Provider errors are reported without exposing keys.
- `src/web/untrusted.ts`: `guardExternalText` removes tag characters, bidi controls and zero-width runs, decodes what hidden tag characters spelled out, and flags instruction-like text. The extension applies it to `web_fetch`, `web_search` and `mcp_*` results. After a flagged result, `bash` commands matching `OUTBOUND_COMMAND` (curl, wget, ssh, scp, git push, gh, npm publish...) need confirmation until the run settles, and are blocked without a UI.

## Skills

`SkillManager` (`src/skills/manage.ts`) applies one `skill_manage` operation. Before touching disk it rejects fields that belong to another action, invalid names (Agent Skills spec: lowercase, digits, single hyphens, at most 64 chars) and text that `scanSkillText` flags (the memory scanner's injection, exfiltration and secret patterns plus download-to-shell, `rm -rf ~`, fork bombs and obfuscated shell). `create` and SKILL.md patches must leave valid frontmatter whose `name` matches and whose `description` is non-empty. Supporting files must live under `references/`, `templates/`, `scripts/`, `assets/` or `examples/`. Writes are atomic. Lint warnings (`oversized-body` past 24,000 chars, `incident-log-shape`, `references-sprawl` past 60 files) are returned but don't block.

Existing skills are located through pi's loaded skills (`getCommands()`), then by searching the user, project, `.agents` and `.claude` skill directories. Skills under `node_modules` or git package installs are locked.

The extension counts tool results per run. When a run reaches `nudgeAfter` (15) calls without a successful `skill_manage` or `memory` call, it starts a background review (`--learning background`, the default): `src/skills/review.ts` condenses the run's messages (from `agent_end`) into a transcript capped at 40,000 chars, keeping the start and the end, and `runSubagent` runs the `learning-review` agent with read tools, `skill_manage` and `memory`. Its last line (`Saved: ...` or `Nothing saved.`) becomes a notification. Reviews are aborted on shutdown. With `--learning nudge`, or when no model runtime is available, the next `before_agent_start` adds a hidden `oasis.skill-nudge` message instead.

## Plan mode

`src/extensions/plan-mode.ts` keeps a process-wide permission mode (`default` or `plan`), shown in the status bar and passed to hooks as `permission_mode`. In plan mode it adds a `plan-mode` prompt section and blocks every tool call that `planModeBlock` rejects:

- `read`, `grep`, `find`, `ls`, web tools, `session_search`, `todo` and `exit_plan_mode` run.
- `bash` runs only when `classifyReadOnly` (`src/shell/readonly.ts`) accepts the command. It parses the command with unbash and checks every simple command, including those inside pipelines, lists, subshells and command substitutions, against an allowlist of read-only programs, git's read subcommands and read forms of `branch`/`tag`/`remote`/`stash`/`config`, and read-only package-manager queries. Write redirects (except to `/dev/null`), `sed -i`, `find -exec/-delete`, `sort -o`, `eval`/`source`/`exec`, function definitions and command names computed at run time are rejected. Anything it can't prove safe is rejected with a reason.
- `task` runs only explore and plan subagents.
- Everything else is blocked.

`exit_plan_mode {plan}` asks the user to approve (a select prompt, then an input prompt for feedback). Approval switches to `default` and tells the agent to implement; rejection returns the feedback and stays in plan mode. Without a UI the plan stays pending and the agent is told to show it and stop.

Subagents with `readOnly` (built-in explore and plan, or `permissionMode: plan` in an agent file) get `bash` plus a guard extension that applies the same `planModeBlock` rules.

## Hooks

`src/hooks/config.ts` merges the `hooks` objects of the user and (trusted) project settings files and implements Claude Code's matcher rules: empty or `*` matches all; only letters, digits, `_`, `-`, spaces, `,` and `|` is a list of exact names; anything else is an unanchored regex. Tool matchers are tested against the Claude name, the OASIS name and, for `task`, `Agent`. `src/hooks/run.ts` spawns `command` handlers through the shell with the event JSON on stdin, `CLAUDE_PROJECT_DIR`/`OASIS_PROJECT_DIR` set, a timeout that kills the process group, and 1 MiB output caps; `http` handlers get a POST. Exit 2 blocks with stderr, other failures are shown to the user and ignored, stdout that is exactly one JSON object is structured output. `combine()` folds parallel runs: any block or deny wins, then ask, last `updatedInput` wins, contexts accumulate. `src/hooks/claude.ts` converts tool names and inputs (`path` to `file_path`, `edits` to `old_string`/`new_string` or MultiEdit, bash timeout seconds to milliseconds) and maps `updatedInput` back through the tool-call repair rules.

The extension sits after tool repair and before safety and the sandbox, so a rewritten call is still checked; a hook's allow never bypasses them. Context from UserPromptSubmit and SessionStart is queued and sent as one hidden message at the next `before_agent_start`; PreToolUse and PostToolUse context is appended to the tool result. Stop blocks become a hidden custom message plus `continue: true` on `agent_before_settle`; the counter resets on every tool call and caps at 8. Subagents load the same hooks at depth > 0 and fire only tool hooks and SubagentStop.

## Subagents

`src/agents/definitions.ts` holds the built-in agents and parses Markdown definitions (frontmatter `name`, `description`, `tools`, `disallowedTools`, `model`, `maxTurns`; body = system prompt). Claude Code tool names are mapped (`Glob` to `find`, `MultiEdit` to `edit`, `Bash(git *)` to `bash`), `*` means every tool. Later sources win: built-ins, `~/.claude/agents`, `<agentDir>/agents`, `<root>/.claude/agents`, `<root>/.oasis/agents`; Claude's names `general-purpose`, `explorer` and `planner` are aliases. Definitions are re-read on every call.

`src/agents/runner.ts` creates a child with `createAgentSession` on the parent's `ModelRuntime` (same credentials and providers), an in-memory session and settings from disk. The child gets `subagentExtensions(depth)` from `src/extensions/index.ts` (identity, instructions, tool repair, safety, sandbox in `inherit` mode, turn gates, and the task tool again below depth 2) plus a role section in its system prompt. Memory, checkpoints and the todo list stay with the parent. Tools: the agent's allowlist, or pi's defaults plus grep, find and ls. The run stops after `maxTurns` (default 40) by aborting on `turn_end`, and the parent's abort signal aborts the child. The final assistant text, cut to 30,000 characters, is the result. With `output_schema`, `src/agents/schema.ts` extracts JSON (fenced, bare or embedded) and validates it; on failure the child gets one prompt listing the problems.

The sandbox runtime is a process-wide singleton, so child sandbox extensions run with `inherit: true`: they copy the main session's mode and roots at start and never initialise or reset the runtime, which would otherwise switch the parent's sandbox off when a child exits.

### Worktree isolation

`src/agents/worktrees.ts`, ported from the original OASIS. With `isolation: "worktree"` the task tool runs `git worktree add -b oasis/<slug>-<hex> .oasis/worktrees/<name> HEAD` from the repository top level (serialized per repository, retried on git lock errors; `.oasis/worktrees/` goes into `.git/info/exclude`) and starts the child in the matching subdirectory. When the child finishes, a worktree with no changes is removed with its branch; otherwise the changes are committed on the branch with `--no-verify`, unless a changed path looks sensitive (`.env`, keys, credentials) or a file contains a secret, in which case the worktree is kept uncommitted for review. The report tells the parent how to review, merge and remove it. Setup files from other tools run in each new worktree, only in trusted projects: `.cursor/worktrees.json`, `.windsurf/hooks.json` `post_setup_worktree`, `.openhands/setup.sh` (`OASIS_WORKTREE_SETUP=0` skips them).

## Tests

`test/harness.ts` builds a real `AgentSession` in a temp directory with an in-memory session manager, in-memory settings, and pi-ai's faux provider registered on a `ModelRuntime`. Tests script model turns with `fauxAssistantMessage`, `fauxToolCall` and `fauxText`, run `session.prompt()`, then assert on files written, model calls made and session entries recorded. No network, no model, about a second for the whole suite.
