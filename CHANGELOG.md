# Changelog

## Unreleased

### Added

- Context savings, ported from the original OASIS: read dedup pointers, superseded `read`/`bash` result stubs once the context is half full, and bash output condensing (passing tests, npm banners, progress redraws).
- MCP: Claude Code's servers (`~/.claude.json` user and local scopes, `.mcp.json` in trusted projects) are registered with pi's MCP client; `OASIS_CLAUDE_MCP=0` skips them. Tool poisoning and rug-pull checks, ported from OASIS 1.x: MCP tool definitions are scanned and fingerprinted on first use (`~/.oasis/agent/mcp-pins.json`), and poisoned or changed tools need approval.
- Protected configuration paths, ported from OASIS 1.x: `write`, `edit` and `bash` changes to settings, hooks, plugins, MCP/LSP config, project agents and commands, git hooks and config, editor tasks, dev containers, direnv, commit hooks and package-manager config need confirmation (blocked without a UI). Symlinked targets are resolved.
- Secret shield, ported from OASIS 1.x: credentials in tool results (Gitleaks rule set, provider token prefixes, `KEY=value` lines, URL passwords, `Authorization` headers) become `«secret:ID»` placeholders in the content and details; placeholders in tool arguments are restored before execution except for `web_fetch`, `web_search`, `task`, `memory` and `skill_manage`. Also exported: `redactSecrets` and `findSecretsInDiff`.
- Web access, ported from OASIS 1.x: `web_fetch` (SSRF-safe with pinned DNS and re-vetted redirects, Defuddle HTML to Markdown, paging, Markdown content negotiation, GitHub blob to raw) and `web_search` (Tavily, Brave, Exa, Firecrawl, SearXNG with reciprocal rank fusion; keyless DuckDuckGo with a Bing fallback). An untrusted-content guard strips hidden Unicode from external results, flags prompt injections and then holds outbound shell commands for approval.
- Background learning review: after a run with 15+ tool calls and nothing saved, a reviewer subagent reads a condensed transcript and saves skills or memories in the background. `--learning background|nudge|off`.
- Skills as procedural memory: the `skill_manage` tool (create, patch, delete, write_file, remove_file) with spec validation, misplaced-field rejection, path confinement, content scanning and lint warnings, a learning nudge after long runs that saved nothing, and `/skills`.
- Plan mode: `/plan`, `/plan <task>` and `--plan` keep the agent read-only until you approve its plan through the `exit_plan_mode` tool. A shell classifier (`src/shell/readonly.ts`) lets read-only `bash` commands through. Explore and plan subagents, and custom agents with `permissionMode: plan`, now get read-only `bash`. Hooks report `permission_mode: "plan"` while it is on.
- Reliability extension. Loop detection: identical consecutive tool calls (arguments compared order-independently) get a note in the third result, are blocked from the fifth and stop the run at the eighth; repeating two- or three-call cycles get one note. Model fallback: `--fallback-model provider/id[,...]` or `fallbackModels` in `~/.oasis/agent/settings.json` or `.oasis/settings.json`; when a run ends in a provider error after pi's retries (context overflow excluded), the next untried model with credentials takes over with a visible notice and a hidden instruction to continue, and the original model is restored when the run settles.

- Hooks in Claude Code's format: `hooks` from `~/.claude/settings.json`, `~/.oasis/agent/settings.json` and, in trusted projects, `.claude/settings.json`, `.claude/settings.local.json`, `.oasis/settings.json` and `.oasis/settings.local.json`; `disableAllHooks`. Events PreToolUse (block with exit 2 or `permissionDecision: "deny"`, `ask` with a confirmation, `updatedInput`, `additionalContext`), PostToolUse (feedback with exit 2 or `decision: "block"`), UserPromptSubmit (block, context from stdout), Stop and SubagentStop (continue the agent, `stop_hook_active`, capped at 8 consecutive continuations), SessionStart (startup, resume, clear, compact; context), SessionEnd and PreCompact (block). Hooks get Claude Code tool names and input shapes and `CLAUDE_PROJECT_DIR`; matchers follow Claude's exact-list/regex rules; matching hooks run in parallel and identical commands once; `command` hooks (600 s default timeout, 30 s for UserPromptSubmit) and `http` hooks. `/hooks` command.

- Subagents: a `task` tool that runs a job in a fresh in-process agent session and returns only its final report (turns and tokens in the header). One `prompt` or a `tasks` batch of up to 8, run 4 at a time; `output_schema` checks the reply against a JSON Schema with one correction turn; `model` (inherit, alias or provider/id) and `thoroughness`. Built-in agents `general`, `explore` and `plan` (read-only tools), plus Markdown agent definitions in Claude Code's format from `~/.claude/agents`, `~/.oasis/agent/agents`, `.claude/agents` and `.oasis/agents` (project agents only in trusted projects), with Claude tool names mapped. Children run with the identity, instructions, tool repair, safety, the parent's sandbox and the turn gates, can delegate two levels deep, stop after 40 turns and follow the parent's cancellation. `/agents` command.

- Project memory: a third memory target, `project`, stored per repository under `~/.oasis/agent/projects/<repo>/memory/MEMORY.md` (4,000 characters) and shared by the repository's linked worktrees and subdirectories. The `memory` tool takes `operations`, a batch applied all or nothing with the size limit checked on the result, so the agent can consolidate a full file in one call. A patch or remove that matches nothing lists the closest entries.

- Project instructions: the Claude Code/Codex/Cursor instruction hierarchy on top of pi's one-file-per-directory loading. AGENTS.md, CLAUDE.md, .claude/CLAUDE.md and CLAUDE.local.md from every ancestor, ~/.claude/CLAUDE.md and ~/.claude/rules, .cursorrules, .windsurfrules, .github/copilot-instructions.md, .claude/rules and .oasis/rules (recursive), and .cursor/rules/*.mdc. `@path` imports (relative or `~/`, four hops, confined to the project and home directory, skipped inside code) and HTML comment stripping. Duplicates (symlinks, a CLAUDE.md that imports AGENTS.md) load once. Rules scoped with `paths`/`globs` frontmatter and context files in subdirectories are attached to the first read/edit/write/ls/grep/find result that touches a matching path, once per session and again after compaction. `.claude/skills` and `.claude/commands` are discovered as skills and prompt templates. `/instructions` command.

- Tool-call repair: calls using Claude Code, Codex, Gemini CLI, Hermes or OpenCode tool names are renamed to the active OASIS tool and their arguments translated (path aliases, `old_string`/`new_string` and MultiEdit edits, Codex argv commands with `workdir`, millisecond timeouts, `update_plan` and `TodoWrite` lists, Anthropic text-editor commands) when the assistant message ends, so the safety policy, sandbox and gates see the real call. Unknown tools get the list of available tools and the closest match.

- Task list: `todo` tool (full-list writes, statuses pending/in_progress/completed/cancelled, one in progress, cancelled items need a note), TUI widget with the open items, `/todos` command, and an open-todos gate that reminds the agent once and then shows "Not done: N tasks still open". Stopping to ask the user a question does not trigger it.

- Memory extension: bounded MEMORY.md (agent notes) and USER.md (user profile) curated with a `memory` tool (add, patch, remove), scanned for prompt injection, exfiltration commands, SSH keys and secrets, and frozen into the system prompt at session start. `session_search` tool: FTS5 full-text search over all past sessions using Node's built-in SQLite, indexed incrementally, plus reading a hit in context. `/memory` command.

- Checkpoints extension: files are snapshotted into a shadow git repository before every user prompt. `/undo` restores the latest checkpoint that differs from the current files (edits and shell changes alike), `/redo` reverses it, `/checkpoints` lists them, and `/fork` or `/tree` to a user message offers to restore files too.

- Test-tamper gate: test and test-config files are snapshotted just before the agent's first edit and diffed with jsdiff at the end of the run. Skips, `.only`, deleted tests or assertions, assertions loosened to truthiness, swallowed assertion errors and `|| true` test scripts trigger a reminder to restore the tests and fix the code, then a visible "Tests weakened" notice. Unlike OASIS 1 (which diffed against git HEAD), the user's own uncommitted test edits are never blamed on the agent.

- Sandbox extension: shell commands run inside @anthropic-ai/sandbox-runtime with `workspace-write` (default), `read-only` and `off` modes; credential files unreadable, network limited to an allowlist with interactive approval of other hosts; `write`/`edit` blocked outside writable roots; `/sandbox` status command. zod is pinned to 4.6.7 through npm overrides to clear GHSA-mrhx-c7xc-m3w5 pulled in by sandbox-runtime.

- Identity extension: the model is told it is OASIS (not "running inside pi") and gets OASIS's working rules as prompt guidelines.

- Ground-up rebuild of OASIS on the pi coding-agent SDK (`@earendil-works/pi-coding-agent` 1.5.2).
- `oasis` CLI with its own identity: app name, `~/.oasis` config directory and `.oasis` project directory.
- Turn gates extension: a turn ledger records edits, failed edits and checks with their real exit status; four gates (failed-edit claim, false pass claim, unverified edits, empty reply) send one hidden reminder each and show a visible notice if the problem remains. At most two automatic continuations per prompt.
- AST-based check detection: recognises `npm run test:unit`, `uv run pytest`, `cargo clippy` and similar, ignores `cat test/foo.js`, and flags checks whose exit status is hidden by `|`, `||`, `;` or `!`.
- Shell safety policy extension: AST-based blocking of catastrophic commands using unbash.
- Model-free end-to-end test harness built on pi-ai's faux provider.
- Research record (`docs/RESEARCH.md`) and architecture notes (`docs/ARCHITECTURE.md`).
- CI on Ubuntu and macOS with Node 22 and 24.
